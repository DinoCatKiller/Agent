对话轮次循环 —— run_round() 在做什么

用户说一句话到「本轮结束」之间发生的事：可能一次模型调用就完，也可能经过多轮「模型 ↔ 工具」往返。 消费者（CLI / 未来 UI / 测试）只看一条 LoopEvent 事件流；内部两条铁律保证状态永远一致。

一次 run_round 的完整路径sync 准备段（可 fast-fail）→ 主循环 → 收尾

消费者看到的 7 种 LoopEventservice.rs → repl.rs / 测试 / 未来 UI

事件时机UI 该做什么
Delta{kind,text}模型增量到达（Text / Thinking）流式追加渲染；thinking 可折叠显示
ModelTurnEnded{finish_reason,usage}一次模型调用收尾并入史可显示「第 n 轮结束」与 token 数
ToolStarted{id,name}工具即将执行显示工具面板「执行中」
ToolFinished{id,ok}工具执行完成（失败也照常回填模型）注意ok=false 不是错误，模型会看到错误文案
RoundEnded{stop,turns,round_usage}本轮自然结束（Finished / MaxTurns）收起输入框禁用态
Cancelled用户取消；之后无任何事件提示已撤销本轮输出
Error{error}终止性错误；之后无任何事件红展示错误；未提交输出已回滚

三条铁律改 service.rs / chat.rs 之前必读

① 只在 End 后入史增量先攒在 TurnDraft，取消 / 出错丢弃草稿即回滚。截断（End{Truncated}）也入史——那是用户真实看到的输出。
② 工具错误喂回模型执行失败、未知工具名都作为 tool_result 文本回传，模型可自救；不做流中重试（重试属 A6），死循环由 max_model_turns 兜底。
③ 历史是事实，请求是视图裁剪只作用于发出去的请求；Chat.messages 永不删改，M5 存档拿到的是完整历史（A7）。
