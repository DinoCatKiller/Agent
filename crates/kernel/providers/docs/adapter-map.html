AGENT-PROVIDERS · M3 · A2-V

适配器边界 —— 「插座」怎么把厂商差异关在门外

编排核心（features/chat）只认识 ProviderRegistry，不认识任何具体供应商。 每接一家模型 = 新增一个实现 Provider trait 的适配器 + 注册表登记一行，核心代码零改动（D2：契约自研、实现可换）。 厂商差异被关在边界内的三个「归一化」里：

一次调用的完整旅程同一套契约类型，两家不同的 wire 协议

两家差异一览同一契约，两种 wire —— 差异只活在适配器 + P1/P2 文档里

OpenAI 兼容族（P1）Anthropic（P2）
鉴权Authorization: Bearer（无 key 不带头）x-api-key + anthropic-version 头
流式形态data-only，[DONE] 收尾命名事件（event: message_start…），message_stop 收尾
工具参数JSON 字符串，跨 delta 分片 → 拼装解析结构化 input，input_json_delta 分片 → 拼装
消息规则system 是 messages[0]；role=tool 回填system 提为顶层参数；role 必须交替，tool 结果是 user 消息里的 tool_result 块
usage 位置末尾一帧（须显式 include_usage）两处：message_start 给 input，message_delta 给累计 output
特有坑role-only 首帧、o* 不收 temperaturemax_tokens 必填、529 overloaded、流中可能来 error 事件
Clone 是硬要求（A2 §2）Provider 因 RPITIT（impl Future 返回值）不是 object-safe；路由层要 dyn 就得把 future 变 owned（let this = self.clone(); async move {…}）。适配器内部用 Arc<HttpClient> 持有连接，clone 只是引用计数，代价为零。
能力协商 fast-fail（A2 §1）请求所需能力必须是模型能力的子集，在路由阶段拒绝——model 不在清单或能力不足（如 vision 打到纯文本模型、JSON schema 打到无 JsonMode 的模型）根本不产生 HTTP 请求（Q1 用例 12）。
