02

crate 依赖图与当前进度

A1 §5 / RM / S1

依赖只能向下。同一层内的多条依赖画成总线，不逐条连线，避免线团；间接依赖由传递性体现 —— 所有 crate 最终都落在 crates/common 上。

已落地 进行中 未建（虚线框） 已规划依赖 规划中（尚未接入）

依赖规则A1 §5 · D5 · 硬约束

  • 只能向下：app → features/* → infra/* → common，禁止反向。
  • infra 不得依赖 features：基础设施不认识业务。
  • feature 之间可互相依赖，但不能成环：crate 依赖图天生无环 —— 这是 D5 选「每功能一个 crate」的核心理由。
  • UI 依赖只在 features/* 与 app：common / infra 永远不碰 GPUI。

读图要点三处容易看漏的边界

  • crates/common 是地面：改它等于改全部，契约变更要先动 A2 / A3。
  • features/* 是界面的唯一出口：界面代码跟着功能走，不再有单独的 UI crate。
  • infra 的六个 crate 互不依赖：transport / providers / routing / store / config / telemetry 各自只挂在 common 上。
03

契约核心：一个 trait、一套事件、九类错误

A2 · 已落地（M1）

这三样东西是「新增供应商零改核心」的全部依据。加一家供应商 = 实现 trait + 注册表登记一行，不动功能切片。

Provider traitcrates/infra/providers/src/lib.rs

pub trait Provider: Send + Sync + Clone + 'static {
    fn id(&self) -> &'static str;
    fn list_models(&self) -> Vec<ModelSpec>;

    fn chat(&self, req: ModelRequest, ctx: CallContext)
        -> impl Future<Output = Result<ModelResponse, ProviderError>>;

    fn stream(&self, req: ModelRequest, ctx: CallContext)
        -> Result<EventStream, ProviderError>;  // 同步返回
}

两个刻意的设计：stream 同步返回——鉴权 / 参数错误必须在发出请求前暴露，而不是等第一次 poll；Clone 是硬要求——trait 因 impl Future 不是 object-safe，路由层要拿到 dyn 就得靠 ErasedProvider 把 future 变成 owned。

归一化流事件Delta 必须可无状态拼接

事件载荷说明
Startresponse_id, model首个事件
Deltakind: Text｜Thinking｜ToolArgs增量，顺序即语义
ToolCallcall分片拼装完成后一次性给出
Usageusage结束前必给一次，缺失也要补默认值
Errorerror之后不再发任何事件
Endfinish_reason末个事件

收尾三分（硬约束）：传输错误 → Error 停止；可恢复坏帧 → 跳过继续；EOF 无终止记录 → 必须补 End{Truncated} 或 Error，禁止静默当成功。

错误分类与默认策略ProviderError · 9 类 · Clone + Serialize

AuthRateLimitTimeoutInvalidRequestServerContextOverflowContentFilterTruncatedUnknown

刻意不用 Box<dyn Error>：错误要进 StreamEvent、日志与 fixtures 回放，所以必须 Clone + Serialize，底层原因以字符串留在 source_message。

三个必须知道的设计决定踩过坑才定下来的

  • JsonMode ≠ JsonSchema：这是两个能力位。合并会把必然失败的请求打到供应商。
  • Truncated 是独立变体：流被提前掐断不能当 Stop。
  • 工具参数在适配器边界归一化：OpenAI / DeepSeek 给的是 JSON 字符串（可能非法），Anthropic 给结构化 input —— 上层只看到结构化 Value。
