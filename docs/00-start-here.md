## 1. 30 秒了解项目

- **做什么**：跨平台桌面客户端，统一接入多家大模型（OpenAI 兼容族 / Anthropic / 本地），流式对话 + 工具调用。
- **技术**：Rust 后端（cargo workspace）；UI 形态待定（见 D3）；契约自研，不绑第三方框架。
- **现在**：架构与契约已定，**尚未落码** → 详见 S1。

## 2. 目录 = 使用场景（先看这个，再看表）

| 目录 | 装什么 | 什么时候看 | 变动频率 |
|------|--------|-----------|---------|
| `10-now/` | 当前状态、未决问题 | **每次开工第一眼**，5 秒确认「现在到哪」 | 高频 |
| `20-spec/` | 规格与契约（改了影响实现） | 动手写代码前 | 稳定，改动谨慎 |
| `30-decisions/` | ADR：记录「为什么」 | 质疑某个决定、想推翻它时 | **只增不改** |
| `40-research/` | 调研证据与对比（过程） | 想知道结论的依据、重新评估选型时 | 一次性，会过时 |
| `50-plans/` | 后期计划（二期 GUI、L3 等） | 做长期排期时 | 低频 |
| `90-templates/` | 文档模板 | 新建文档时 | 稳定 |

**一句话**：想知道「**做什么**」看 `10-now`，「**怎么做**」看 `20-spec`，「**为什么**」看 `30-decisions`，「**凭什么**」看 `40-research`，「**以后做什么**」看 `50-plans`。

## 4. 三条阅读路线

| 谁 / 什么场景 | 路线 |
|--------------|------|
| **人，第一次了解** | 本文件 → S1 → G1 → A1 → A2 → 按需进 D1/D2/D3 → 需要证据才看 40-research |
| **Agent 接任务** | `AGENTS.md` → 本文件 §3 命中 1–3 行 → 只读命中文档 |
| **想推翻某个决定** | 对应 `D*` → 它引用的 `40-research/*` → 写**新** ADR（旧的不改） |
| **想动手写代码** | S1 → S2 → A1 → A2 → 对应 spec（⬜ 的先按模板补） |

## 5. 上下文预算（给 agent 的硬约束）

| 项 | 预算 |
|----|------|
| 常驻 | `AGENTS.md`（≈1k token），其余**默认不读** |
| 单任务 | 最多 3 篇 / 约 6k token |
| 单篇 | 先读 TL;DR 段，不够再往下读 |
| 超预算 | 先把结论写进 S1 摘要，再继续；不要把全文塞进上下文 |
| 单篇上限 | 超过 ~300 行必须拆分并登记 |

## 6. 文档守恒规则

1. **一个结论只有一个家**（single source）。其他文档只许链接，不许复制——复制是「层次感消失」的根源。
2. **未决问题只写在 S2**；其他文档里的「待定问题」一律改成指向 S2 的链接。
3. 改了 `20-spec/` 必须检查 `30-decisions/` 是否冲突；冲突就写**新** ADR 覆盖，**不改旧 ADR**。
4. 新建文档：复制 `90-templates/doc.md`，写好头部元数据，并在 §3 登记。
