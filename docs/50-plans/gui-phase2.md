## TL;DR

- 二期做 GUI，前置条件是 Core 已跑通（M1–M4）且 D3 已定。
- 二期同时启动 **L3：CSS 兼容层**——把 CSS 运行时语义做出**子集**，让 Web 样式资产可直接喂入。
- L3 分 4 级递进（L3.1 → L3.4），**每级都有停止条件**；若成本超过「换 Tauri」的代价，就停手改走 WebView。

## 3. L3 · CSS 兼容层（本计划新增的核心项）

### 3.1 目标

在 GPUI 之上实现 **CSS 语义子集**，使 Web 侧样式资产（含 CSS 变量、类名、状态选择器）可以直接用于界面，而不必改写为 Rust 方法链。

> 为什么放后期：成本≈实现一个简化版 style 系统；一期用 token 层（L1）已能解决 ~80% 的观感需求，先把主干跑通更重要。

### 3.2 分级路线（逐级可停）

| 级别 | 内容 | 价值 | 成本 | 停止条件 |
|------|------|------|------|---------|
| **L3.1** | CSS 变量与设计令牌互通（`--color-surface` ↔ Rust Theme） | 主题/KV 免费复用 | 低（一期已部分覆盖） | 无，必做 |
| **L3.2** | 类名 → 样式子集（utility 映射，即 `tw!` 宏的运行时/编译期版） | 写样式像写 Tailwind | 中 | 覆盖常用 utility 后停止扩张 |
| **L3.3** | 选择器 + 层叠 + 伪类（`:hover`/`:focus`/`disabled`）、后代选择器 | 可直接吃现成 CSS 片段 | **高** | 若需要支持「选择器优先级计算」才能继续，则停手评估 |
| **L3.4** | 媒体查询 / 容器查询 / `@keyframes` / 过渡 | 响应式与动效 | 高 | 若 GPUI 上游出现原生支持，改为跟随上游 |

### 3.3 设计约束（若启动）

- **解析结果必须缓存**：样式表解析成不可变的样式对象，挂在 `Entity` 上，禁止每帧解析。
- **不引入脚本**：只做声明式 CSS 子集，不做表达式求值（避免变成 JS 引擎）。
- **不碰 GPUI 内部**：只通过公开 API（含 `STYLE_METHODS` 反射表）注入样式，避免绑死内部结构。
- **可降级**：任何无法映射的 CSS 属性必须**告警并跳过**，绝不 panic；并输出「未支持属性清单」供人工判断。
- **上游风险**：GPUI 仍 pre-1.0，L3 会放大升级成本 → 与 `agent-ui` 一起隔离在同一 crate 组内。

### 3.4 逃生通道

若 L3.3 的实测成本超过「切换到 Tauri（真 CSS）」的迁移成本，则**放弃 L3**，走 WebView 路线。判断标准在 L3.3 启动时先写死（例如：连续 X 周未达可用状态，或需要改动 GPUI 内部）。

## 4. 已识别风险

| 风险 | 缓解 |
|------|------|
| L3 变成无底洞 | 四级递进 + 每级停止条件 + 逃生通道（§3.4） |
| GPUI pre-1.0 破坏性升级 | UI 相关代码隔离在 `agent-ui*` crate 组；固定 `gpui-kit` 版本 |
| 组件实现工作量被低估 | 一期只做界面必需组件，对标 shadcn 分批移植 |
